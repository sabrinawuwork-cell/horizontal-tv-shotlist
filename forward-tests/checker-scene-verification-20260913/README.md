## 验证对象和方法

使用既有匿名案例《我问的是他》的当前批准分镜：三人、33秒、5镜、2个生成任务，包含王岚右手前臂托盒、落桌释放、陈旭离开并被叫停、推盒、欲言又止、让位与转身。保留原输入、批准方案、Stage1/2；只在隔离副本中补齐新版发声记录。没有拿过去的验收结论当本轮答案。

正常制作代理只获批准上游与候选技能，没有得到旧Stage3或本轮错误答案；重新编译并执行原有自查，保留首稿/中间稿/最终稿。另由三个全新上下文的Astra medium代理分别只读审查正常稿与两个挑战包，先仅看真实提交内容，再开放上游；未向审读者提供改动位置或真值。独立角色是本轮验证措施，未给项目新增常设审核层或用户审批。

验证前准备7处语义错误和4处合法改写，具体内容封存在[truth.json（本机归档）](../../docs/验证材料索引.md#checker-scene-verification-20260913 "原路径：truth.json")。两份挑战稿在候选程序均通过，正用于检查AI能否承接程序不判断的内容。设错并修复不是新导演能力证明；正常重编译没有注入错误。

## 实际结果

- 两份挑战稿：7项预设错误全部被独立审读发现；4项合法改写没有被要求改回指定字词。分别见[审读K（本机归档）](../../docs/验证材料索引.md#checker-scene-verification-20260913 "原路径：review-k.json")、[审读R（本机归档）](../../docs/验证材料索引.md#checker-scene-verification-20260913 "原路径：review-r.json")。
- 检出的错误包括：机位换到轴线另一侧、情感解析里凭空新增发声、推近后的盒子跨任务回到原位、台词文字不变但说话者错换、无依据加羞辱怨恨、下一任务缺人物外观与道具定义、把转身提前到下一任务初态。
- 主持按独立报告做最小修复，未改上游和4处合法表达；两个原审读者限定复核确认7项已解决且未引入新问题。见[修后核验（本机归档）](../../docs/验证材料索引.md#checker-scene-verification-20260913 "原路径：verification-after-repair.json")及packet-k-repaired、packet-r-repaired的实际delivery。
- 正常重编译：制作代理自修参考标签分隔、转身后光态的叙述位置；最终两份实际请求经独立审读未发现确定错误。五句对白归属、陈旭无声、王岚未出口、手物顺序、两任务的起止状态及最后沉默保留。见[正常稿自查记录（本机归档）](../../docs/验证材料索引.md#checker-scene-verification-20260913 "原路径：normal/output/self-check.md")、[独立正常稿审读（本机归档）](../../docs/验证材料索引.md#checker-scene-verification-20260913 "原路径：review-normal.json")。
- 内容任务27.5/5.5秒，按本案例给定入口规格另交28/6秒请求，每份0.5秒末态余量标为弃用；成片仍33秒。请求正文与引用摘要一致。没有调用在线入口认证其现行规格。

## 与旧版的区别

[公开入口对照（本机归档）](../../docs/验证材料索引.md#checker-scene-verification-20260913 "原路径：program-comparison.json")显示：旧版在K包同时挡住两处真实错误和一处合法改写；R包四处真实错误则新旧程序都没有识别。因此旧版程序本来也不能替代内容审读。

K包修正后，AI复核已确认三项内容错误解决，旧版仍因1A“摄影机位于床南側……”而误拦；候选版正常通过。R包修后两版都通过，正常重编译的最终稿两版也均通过。这支持“减少检查器带来的不必要返工”，不支持“凡是新版产物都会明显更好”。

## 替换判断与边界

本轮已为AI承接内容复核取得正向证据，并且没有修改候选运行代码来迎合结果。结合此前209项程序测试，支持替换；预期收益集中在表达保真和交付过程，无法量化总体质量提升幅度。

这是一个完整既有场景、两份人工设错变体和一次正常重新编译。7/7是本次命中数，不是100%可靠率；独立上下文的能力表现不能冒充所有单代理自审都稳定。导演方案与Stage1没有重新创作，不能据此说分镜设计能力提高。最终正常稿未显式带出所有布景坐标/尺寸，精确构图、家具位置和真实生成的身份/手指接触仍未证明；没有将这些未知强判为已发生错误，也不拿其遮盖可直接判断的文本问题。
