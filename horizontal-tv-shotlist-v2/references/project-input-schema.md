# 当前项目输入与导演选择

具体项目事实、授权和偏好保留在项目文件中，不写死进技能。代理从当前用户指定源和已有项目记录核实版本与范围，不用文件修改时间、旧分镜或“看起来较新”的名称代替权威。

## 实际输入

- 当前剧本与范围、项目/集/场标识、画幅、拍摄语言及已有风格约定。
- 场景结构与参考图：真实门窗、通道、家具、地标、光源及已知尺寸；人物/道具/服装参考，身体、伤势及操作限制。
- 剧本或用户已确定的站位、朝向、进出和动作结果；没有指定的调度、机位、局部轴、观看顺序由导演决定，不作为必需用户输入。
- 实际模型版本与产品入口、请求时长范围/步进、画幅/清晰度、可用参考/生成/后期条件，以及镜号级制作例外。源镜/内容任务时长与实际请求参数分别判断，缺入口时不假装已核实平台可接受。
- 当前项目的词表、对白保留授权、是否启用音色；`voice_prompt_required`默认`no`。已获得的同项目同范围授权继续有效，不因为进入下一阶段重新索取。
- 新建或更新交付：目标文件/版本、工作表、镜号和可写范围、受保护行/区域、输出路径。对原表的有效用户改稿先与权威Markdown协调，不直接用旧Markdown覆盖。

导演在方案中决定未被锁定的动线、轴线、观察位置、表演细化、节奏与视觉/声音方式，并检验它们与事实和制作条件相容。

## 处理不确定性

事实缺失先查现有素材，影响关键结果才询问；开放的导演选择由代理给出有依据的方案。制作能力尚缺证据时标记需要的试位/生成验证，并推进不依赖它的工作。涉及改变剧情、已定风格、明显费用或不可逆影响的取舍，准备具体可评估的选项后再请用户裁决。

不虚构已测尺寸、灯光数值或参考图外观。项目/集号缺失不妨碍有明确范围的草案使用描述性标识，但不能用占位符声称正式批准。Stage 3需要真实的权威来源与当前项目身份；由本阶段补造来源或批准是错误。

## 声明额外使用的输入与策略

原有 `source/source_sha256`、场景图摘要及对白清单继续保留。使用独立场景事实文件时，在Stage 1声明成对的 `scene_facts`、`scene_facts_sha256`；方案引用该文件时也绑定同一实际文件。

其他实际使用的角色、道具、补图或制作条件文件，可在Stage 1声明 `input_manifest` 与 `input_manifest_sha256`。清单路径相对其自身文件：

```json
{
  "inputs": [
    {"role": "production", "path": "production-conditions.md", "sha256": "实际摘要"}
  ],
  "policy": {
    "lighting_mode": "descriptive",
    "sensitive_terms": ["医护"],
    "dialogue_sensitive_authorizations": []
  }
}
```

例子中的项目词不是通用禁词。`inputs`可以为空（只有策略时）；`policy`可省略。V2默认光影使用有依据的描述；项目明确要求数值控制时设置 `lighting_mode: numeric`，缺失K/亮暗lux才成为格式错误。实际给出的数值也须区分测量、设计目标和生成控制，不能冒充实测。追加词表只检查不改字，已明确授予的对白保留词可记录在清单或既有Stage 3授权字段；授权不扩展到其他项目。

Stage 2/3从真正引用的Stage 1继承策略，不能各自写另一个覆盖值。所有已声明文件及摘要在各阶段重新核对；未使用额外文件的旧稿不强制造清单。清单只能证明已声明输入的一致性，不能证明漏报输入不存在、源是最新版、人物归属或动作语义正确；这些必须对当前任务与实际产物复核。
