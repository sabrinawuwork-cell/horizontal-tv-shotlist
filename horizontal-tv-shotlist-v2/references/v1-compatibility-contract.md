# V1 兼容性契约

V2 必须以 V1 为完整基线。除用户明确批准的 V2 差异外，V1 的规则、示例、输出字段、字段顺序、句式和验证行为全部原样继承；不得把“独立 V2”解释为脱离 V1 重写。

## 不可擅自改变的格式

- Stage 1 固定七列及顺序：`场次｜镜号｜时长｜摄影机｜画面内容｜音效｜剪辑衔接`。
- 镜号使用场次加字母，跳过`I/O`；插镜使用`3B-1`；覆盖使用`3B-COV1`；局部修订不得重排无关镜号。
- `摄影机`必须完整执行[七列输出 Schema](output-schema.md)和[Stage 1 摄影机与画面书写规范](stage1-camera-picture-writing.md)，包括固定顺序、数值焦段、单人相对机位、双人景别身体截取、OTS、POV、特写及固定/手持/运动写法。
- `画面内容`、`音效`和`剪辑衔接`继续执行 V1 原规则，不因 V2 新导演方法改变文字容器。
- Stage 2 继续采用 V1 的一类一卡片格式；只有“音色默认可不建立”等用户明确批准的 V2 行为可以覆盖对应判断。
- Stage 3 固定五列及顺序：`镜号｜片段｜时长｜分镜内容｜Seedance提示词`；只有实际存在问题时才增加`备注`列。
- `分镜内容`继续逐字合并 Stage 1 的`摄影机`、`画面内容`和`音效`，三类之间空一行，不包含`剪辑衔接`。
- Seedance 提示词继续保持每个类别之间换行并空一行，镜头首句继续使用片段内`开始秒数-结束秒数`。

## 唯一允许覆盖 V1 的已批准差异

1. Stage 2 approved 且生成前检查通过后，Stage 3 直接输出完整展开固定类别正文的`approved`，取消 Stage 3 draft、类别名称占位和二次批准。
2. Stage 2 基础音色默认不创建；只有用户在当前任务中明确要求音色提示词时才创建。
3. 每次生成 Stage 3 前执行全题材平台敏感词预检，并保护受保护对白。
4. 按需加载战争历史背景＋医疗正剧题材模块及其已批准方法。
5. 增加匿名历史制作问题回归、物理光影写法、群演分层、景别升级、反应覆盖和30度规则；这些新增方法不得重定义输出格式。
6. 用户明确要求从下一次任务开始，在 Stage 1 提交批准前按当前主序列实际行序把镜号归一化为连续字母并跳过`I/O`；临时插镜后缀仅供修订过程使用，不得进入 Stage 3。该归一化只改变镜号及其引用，不改变镜头内容、顺序或覆盖命名。
7. Stage 1时长改为从台词、动作、反应和沉默反推，不再先套`5–10s`默认值；`20–30s`镜号级授权和`30s`硬上限不变。
8. Stage 1增加场次首镜空间建立、内部人物状态账本、观众信息揭示顺序、长演讲反应覆盖和复杂调度结构化检查；这些均是内部决策或内容质量规则，不新增输出列。
9. Stage 2增加室外持续环境卡必要性判断和人物—机位—光源内部映射，不改变一类一卡的审核容器。
10. Stage 3默认禁止`【角色名音色参考：】`块；只有用户在当前任务明确启用音色时才允许。该差异不改变Stage 3五列、类别顺序或其他写作标准。

没有列在本节中的差异一律视为未授权回归，必须退回 V1 原行为。

## 必须加载顺序

1. 先读取 V1 当前阶段的全部必读规则与精确 Schema。
2. 再读取对应的`v2-*-authorized-additions.md`。
3. 只有本文件列出的已批准差异可以覆盖 V1 对应条款。
4. 最后同时执行 V1 Checklist、V2 新增 Checklist 和回归检查。
