# 更新指定现有工作簿

Markdown继续作为本次权威底稿。用户已在原表做了有效修改时，先读取并协调到本次底稿；不能拿旧Markdown覆盖用户改稿。新建工作簿仍使用原导出器。更新已有文件时使用 `scripts/update_workbook.py`，不把新建导出冒充原表更新。

## 明确目标与范围

先从当前任务核对实际文件、版本、工作表、表头行、可写区域、被保护的首条分镜/首行及其他范围。“首行”可能指第一条数据，不能只保护工作表第1行。工具只更新指定数据值，不插删行，不改表头、样式或其他工作表。列映射外的同排单元格保留。

以JSON记录这次有界操作；路径相对范围文件或使用用户已指定的绝对路径：

```json
{
  "workbook": "existing.xlsx",
  "sheet": "全集分镜",
  "header_row": 3,
  "start_row": 5,
  "writable_range": "B5:H10",
  "columns": {"场次":"B","镜号":"C","时长":"D","摄影机":"E","画面内容":"F","音效":"G","剪辑衔接":"H"},
  "shots": ["1B","1C"],
  "expected_existing_shots": ["1B","1C"],
  "protected_ranges": ["A4:J4"],
  "clear_tail": false
}
```

Stage 3按其五列或实际六列映射。`shots`明确本次源镜号，`expected_existing_shots`明确目标区目前应有的镜号，不能凭行数猜测。数据缩短只有显式 `clear_tail: true` 才清理旧尾；增长只能用授权范围内已有空位。不能无限清空表尾，也不为扩容移动其他行。

## 预览、应用与回读

```sh
python3 scripts/update_workbook.py --input authority.md --spec update.json
python3 scripts/update_workbook.py --input authority.md --spec update.json --apply --expected-target-sha256 <预览摘要> --expected-plan-sha256 <预览计划摘要>
```

先生成操作预览，确认源文件通过当前V2入口、目标/表头/镜号相符、变更仅落在授权区，再按用户已有授权执行。不新增用户审批轮；权限或范围未给定时先把操作对象做具体再裁决。apply重新核对源、范围和目标，并以原子替换保存；预览后发生变化要重新核对，不能继续用旧计划。Python `apply_update(plan)`绑定整份预览；CLI总是使用当前源和spec，传入plan摘要可额外绑定旧预览。

工具保留非目标ZIP部件和目标单元格原样式，只替换数据值；其他公式的文本与缓存不改写。更新后再打开/读取关键表值，原生Excel显示、公式/图表重算及长文本裁切仍要按实际交付检查；不能把字节保留当作显示和计算已验收。

## 明确的不支持范围

只处理普通未加密 .xlsx 的现有数据区域。不扩出现有工作表范围，不调整结构化Excel表行数；目标公式、合并、富文本、受保护或无法保真的扩展元数据会拒绝。宏、数字签名和不明确的文件结构也不处理。需要这些变化时保留原文件并报告具体范围，不退化成整表覆盖。文件系统与不遵守锁的外部写入之间仍有竞争窗口，不声称跨应用事务保证。

若 Stage 1 带有[修订记录](shot-revision.md)，预览额外给出完整旧新镜号映射，并核对当前目标区的旧主镜不会被插镜挤掉或被不相关旧镜替换。主序列插镜需授权空位；带修订的覆盖表更新另行核对。预览与 apply 绑定实际当前来源及必需历史编号节点的初始摘要和文件状态，旧稿、修订记录、旧连续性记录变化或改后还原均使旧预览失效。
