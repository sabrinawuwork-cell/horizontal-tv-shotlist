# 生成任务与成片素材映射

Stage 1 主序列和 Stage 3 五列表始终按成片顺序排列。`片段` 列引用生成任务；任务自身的时间线与成片时间线分别记录。一次任务可以提供主表演前后两段素材，成片在二者之间插入另一个任务提供的反应。

没有生成计划时，保留现有连续片段规则：片段从1递增，不能返回旧片段。只有显式绑定、文件摘要及内容检查全部通过的计划，才能启用 `片段1 → 片段2 → 片段1`。这不是放开任意重排或自动延长。

## 计划声明

在 Stage 3 frontmatter 中成对声明，路径相对 Stage 3：

```yaml
generation_plan: generation-plan.json
generation_plan_sha256: <计划文件的真实SHA256>
```

计划为 JSON。以下示意中摘要占位符必须替换为真实文件摘要；Stage 1 必须确实包含所引用的剪辑原文。

```json
{
  "version": 1,
  "source_stage1_sha256": "<当前Stage1的真实SHA256>",
  "tasks": [
    {
      "id": "片段1",
      "clips": [
        {"shot": "1A", "in": 0, "out": 4},
        {"shot": "1C", "in": 4, "out": 8}
      ],
      "references": [
        {
          "label": "@Image 1",
          "path": "assets/character.png",
          "sha256": "<参考文件的真实SHA256>",
          "use": "角色甲的身份"
        }
      ],
      "reuse_basis": {
        "reason": "主表演素材前后接续，反应独立生成后插入成片。",
        "stage1_evidence": ["甲的表演持续，切乙的反应后回到甲，接续同一段表演。"]
      }
    },
    {
      "id": "片段2",
      "clips": [{"shot": "1B", "in": 0, "out": 4}],
      "references": []
    }
  ]
}
```

- `tasks` 按任务在成片中首次出现的顺序编号，目录严格为 `片段1` 到 `片段N`。表中仍为 `1A / 片段1`、`1B / 片段2`、`1C / 片段1`。
- 每个 Stage 1 主序列镜头完整且只映射一次。任务内部 `clips` 保留这些镜头在 Stage 1 的相对顺序，不能倒排、漏镜或重复镜头。
- `in/out` 为 JSON 数值，单位秒。每个任务从0连续计时，无重叠或空洞；每段长度等于对应 Stage 1 镜头时长。Stage 3 提示词开头写任务时码，例如上述 `1C` 是 `4-8秒。`，而不是成片位置 `8-12秒。`。
- 同一任务不能跨 Stage 1 场次，累计不超过30秒。任务首镜必须自足；回到已有任务的后续镜头按该任务内部顺序衔接。
- 非相邻素材复用必须填写 `reuse_basis`。`reason` 说明制作理由；每条 `stage1_evidence` 必须是该任务覆盖区间内 Stage 1 画面或剪辑字段中的实际原文。程序核对来源存在，不判断这段文字是否足以支持该拍法；执行者仍须对照原意复核连接、物理空间与时间连续性。
- `references` 必须是数组，没有素材时写 `[]`。路径相对计划文件，每项绑定实际文件摘要，`use` 是非空用途说明，允许自然换行，导出保留其文字。`label` 为单个 `@` 标签，如 `@Image 1`、`@Video 1`、`@图片1`、`@角色甲`；同一任务中唯一，不同独立提交的任务可以使用各自的 `@Image 1`。提示词出现的非对白参考标签必须在该任务声明。正文优先按完整编号标签和本任务已声明名称识别，允许紧接中文（如`@Image 1与@Image 2`、`@角色甲的外观`），不要求为识别添加空格；长名称优先，`@Image 10`不当成`@Image 1`，普通邮箱不当成素材引用。

计划改动、参考文件同名替换、来源摘要失配或表中任务引用与计划不一致都会失败。更新摘要只表示换了文件绑定，不自动证明已完成内容复核或上游批准。

## 任务首稿组织

在写独立任务的第一份提示词前，先沿当前上游的 `scene_facts`、`input_manifest` 和资产绑定读取必要条件，结合任务覆盖的镜头判断实际承载方式：影响本任务拍法、动作或接续的场景布置、人物身份、身体与道具限制、表演条件及开始状态，必须由任务正文或本任务实际随附参考给出。来源路径、摘要、Stage 1 已写过、Stage 2 未建卡，都不能代替模型接收这些内容。先落实承担方式，再删真正重复或与本任务无关的信息；不要求另交清单或照抄所有坐标、尺寸。

沿用五列和已有提示词块组织，不新增任务字段或固定卡类型：

- 场景的必要空间关系在本任务首镜的 `画面：` 中用自然句说明适用于本段布景，随后明确当前构图实际可见的范围；说明布景不要求把全部陈设拍进首镜。只影响后续局部镜头的条件也可在对应镜头写明。
- 无实际身份参考时，人物外观写在该人物于本任务首次入画的镜头，后续沿同一姓名接续；道具定义随本任务首次需要生成该道具的镜头给出。若首镜只拍甲、下一镜才拍乙丙，首镜只定义甲，乙丙的必要外观在下一镜定义。画外声源或视线对象按既定关系写姓名与必要方位，不附带其不可见外观或动作。
- 身体限制、接触与持物条件在相关动作发生前写足；各镜的起态、表演变化、声画与切出仍按批准事件在原画面、动作或声音块表达，不把动态条件提成全段不变状态。跨任务首次入画仍需独立定义，不能指望模型记得上一任务。
- 省略参考已表达的文字，只限本任务实际绑定且经查看确认承担该属性的素材和用途。材质参考不替代指定布局，场景图不替代人物身份；只用于身份的图也不决定当前姿态或站位。必要文字与参考冲突时明确实际用途和当前权威条件，不能用“参考图优先”覆盖已经批准的布景或调度。真实参考确已承载的外观不必重复抄写，不伪造缺失素材。

必要条件有承担方式后，按[镜头正文的写作顺序](v2-model-seedance-2.5.md#执行展开与导演边界)从导演意图写出具体演出、观看与声画过程，再整理进现有类别。素材与初态准备完成不等于镜头已写完；完整正文在首次排表和导出前形成，不留给交付审读补写。空间数据按[空间表达与参考](v2-model-seedance-2.5.md#空间表达与参考)转译。首稿写作直接完成在原交付中，不增加字段、单独产物或审核层。

## 导出完整任务

```sh
python3 scripts/generation_tasks.py --stage3 /实际路径/stage3-approved.md --output-dir /实际路径/task-export-v001
```

导出开始时保存实际声明输入的内容摘要与文件身份，编译只使用本次Stage 3文本快照；写出前复核完整输入链，期间变化则拒绝且不创建任务包。来源记录永远指向真正编译的初始快照，不临时用新摘要标记旧文本。最终复核后的外部编辑不追写进来源，提交前仍应检查所选版本是否当前有效。

导出入口内部只运行一次当前V2 Stage3检查，并复用该次取得的已核对镜头和来源，沿真实引用核查Stage1、全部Stage2、项目输入、编译卡映射及可选生成计划，不要求事先再单独调用一次。默认音色行为保持；既有明确音色参考授权仍可通过 `--allow-voice-reference` 传入。输出目录须不存在或为空，避免覆盖现有文件。 同一任务的标签规则只建立一次，同一计划中重复引用同一实际文件时复用本轮素材版本核对结果；不建立跨导出的缓存。完整输入快照与写出前一致性复核仍保留，正常通过不增加使用者确认步骤。

同类视觉固定卡在最终正文中可共用一个类别标题，各卡正文按已选顺序完整拼接，不改写、不删句。检查与导出采用相同的组装规则；卡片管理仍保持原分类，不因标签合并改变事实。

输出包括：

- `task-001.txt` 等：每个生成任务一份完整可复制文本，包含已声明的参考用途、共同固定条件、按任务时码排列的镜头文本及末尾限制。
- `references.json`：按任务列出引用标签、实际文件绝对路径、摘要和用途。工具不上传或复制参考媒体；提交前仍要把这些文件绑定到对应标签。
- `edit-map.json`：原 Stage 3、Stage 1、Stage 2 和可选计划的路径与摘要、完整已声明输入快照、任务目录，以及按成片顺序排列的镜号、任务、素材 `in/out` 和成片 `timeline_in/timeline_out`。

任务内去重只适用于每个镜头都选用了各自批准卡、且组装后正文独立并逐字相同的光影、背景、环境、群演或外观块。公共块移到任务开头保留一份；只适用部分镜头或不同正文的卡、单镜例外都留在原时间段。声音/对白块不拆分，不因文字重复就提到全局。每个独立任务开头固定为 `全片要求：不添加背景配乐，不生成字幕。`，末尾保留 `无配乐无字幕`；不追加其他全片要求解释，作者不必逐镜写固定尾句。已知旧尾句的标点/空格可机械整理；任意等义表述及其余原文限制、对白保持原样，不用关键词判断它是否准确。内容复核确认不存在相反要求。

无计划的有效旧稿也可以导出，仅按其连续片段组织任务，不补参考、不重排镜头。若旧稿提示词含尚未绑定的参考标签，须先明确实际素材与计划，导出不会凭空补齐。

## 内容时码与实际请求参数

上述任务时长和`in/out`表示已定内容，不自动等于任意入口接受的请求参数。准备实际制作时先核对所用入口的最短/最长时长、整数或步进要求及画幅/清晰度；不要把27.5秒内容直接传给只接受整数的参数，也不能把独立短尾镜强行并进不同物理场景。

Stage 3 权威提示词及绑定计划中的实际参考用途共同提供任务内容；task 由当前版本导出，request 从该 task 派生。request 只处理入口参数、必要的时长表述和合法余量，不另行增删场景、人物、道具、表演、对白或连续性内容。发现重要遗漏时，回到 Stage 3 主稿或对应参考用途修正，更新实际变更文件的版本/摘要后重新导出，并同步 request 和现有交接引用；上游决定有误则先修对应上游。旧交付保留追溯，不能把较完整的 request 与未同步的主稿/task 作为同一有效版本交付。派生后对照 task 与 request 的正文，除已说明的参数和余量处理外应传递同一内容，不以摘要一致代替内容判断。

若只需少量剪辑余量，可在当前制作交接中另列请求时长、实际提交正文、对应内容任务及摘要、保留区间和弃用区间。依据末镜实际状态安排余量，不新增剧情或改变保留区内的时码、动作速度和导演时长；持续运动与静止镜尾分别处理。实际请求仍遵守本项目30秒上限。没有必要余量时直接使用内容任务，不制造额外版本。

这类提交说明绑定实际选定入口与本批产物，不是新通用平台或自动提交器；已有导出工具不认证平台参数，也不会自动补余量。单镜仍只用一次生成素材，余量不进入成片映射，不是延长链。内容时长与入口要求不能兼容时回到制作取舍，不能静默重导。真实生成继续受用户授权约束。

## 接收式审读实际交付

用本节替换“已经知道方案，再把请求通读一遍”的做法，仍属于原有交付前内容审读，不新增审批层或必交报告。先选定真正会提交的正文、参数及实际随附参考；来源路径、摘要、导演方案和之前任务不是模型自动得到的上下文。

**先只据实际接收内容经历镜头，再对照源。** 从起幅沿真实时序读出摄影机让观众看见什么、动作怎样发生、人物怎样发声和接收、关键声音何时介入、光影和构图怎样变化，直到切出及余韵。判断这些具体表达是否实现了本镜意图、分寸和节奏；已有节点能对上，只能说明未漏项，不能单独判为写作完成。审读负责发现偏差，不承担把分镜简述扩写成成品的常规工序；核对分类块之间的先后/同时、触发和结束是否一致，时间能否容纳。身份、场景、身体与手物条件仍须自足。区分明说、可推出和未知，不借上游解释补正文的洞，也不要求每镜复述参考已承载或画外不需要的内容。

完成这一步后才对照当前剧本、导演方案、Stage1/2、制作条件及实际任务映射。对已经确定且影响本任务拍法、动作或接续的条件，核对实际正文或随附参考如何承载；必要条件只留在上游、没有传给模型，是需要补齐的交接遗漏，不能仅归为“精确效果尚未验证”。真正未提供或未验证的事实才保留为未知。参考已经承载、当前构图不适用或不影响执行的信息可以不重复，不机械照抄全部数字，也不把画外事实补成入画动作。

同时核对全部实际发声与原剧本的原文、顺序和归属，不只比较编译记录选中的台词；核对固定卡适用范围、独立任务初态与故事时刻，以及换机位后是否残留旧左右、背景、可见面或声画关系。修订或替换交付时，直接比较同一范围的旧新正文：剧情与观看意图、摄影可读性、身体与表演、节奏声画、空间参考及收束是否得到保留和充分实现，具体展开是否改变了原意。不能以更短、更长、某块是否出现或局部错误减少替代整体质量判断。发现遗漏、越界展开或时间冲突，修对应源头并同步派生；用现有修订说明记录，不新增审核阶段、评分表或逐镜账本。

对源时一并处理入口输出的非阻塞`WARNING`或当前`edit-map.json.content_warnings`中的运动差异线索，按[V2输入与编译记录](v2-authority-and-continuity.md#创作表达与上游一致性不能混为一类)区分等义表达与实际改动。确认等义可保留原句；真实变化/遗漏在原步骤修正。不要跳过提醒，也不为清空提醒改写正确文本；这仍是本段已有内容自查，不追加一次评审。

可用独立上下文进行既有审读时，先只给实际提交内容和随附素材，完成还原后再开放来源；不要先让它通读方案和作者自评。由原执行者自审时同样限定证据来自实际提交内容，但不能把它称为独立盲读。设计错误回到设计，表达不准修源句，下游遗漏修丢失处，评审假设不成立就撤回意见；不让用户逐镜补齐这些内容。

## 验收边界

这是素材任务编排与文本导出，不是新视频平台。当前未实现超过30秒单次任务、延长链、单镜拆成多次调用或同一完整镜头多次占用成片；有这些需求时保留原创作，明确指出尚未实现的制作路径，不能静默压缩或分镜。

程序不从文学文本证明所有物理空间、表演连续性、声音同步或模型稳定性，也不验证参考素材的身份语义、平台媒体规格和实际上传槽位。导出成功只证明这些声明和文本通过了所列检查；真实生成、素材接受和成片验收仍分别验证。

已批准 Stage 1 有局部修订或重编号时，任务中的 clips/编译记录须使用通过验证的当前 ID，Stage 3 不单独归一化。导出的 `edit-map.json.shot_revision` 包含实际记录、旧稿摘要和完整旧新映射；历史编号链与纯重编号用到的旧连续性记录进入快照，不将过期历史剧本或资产当作当前生成来源。参见[修订协议](shot-revision.md)。
