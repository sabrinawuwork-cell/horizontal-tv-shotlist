# V2 权威输入、可见性与编译记录

本文件规定当前项目的输入与编译绑定，不承担导演创作方法；先方案后拆镜执行 director-core.md。保持七列/五列、Stage 3 直出 approved 和情感解析规则。配套记录由代理维护，不新增交付列或用户审批轮。

## Stage 1

在既有 frontmatter 增加以下字段；路径相对所属 Markdown，摘要按文件原始字节计算：

```yaml
source_sha256: <source 文件摘要>
director_plan: director-plan.md
director_plan_sha256: <拆镜依据的导演方案摘要>
scene_images_sha256: {"1": "<场次1场景图摘要>"}
dialogue_manifest: dialogue.json
dialogue_manifest_sha256: <对白清单摘要>
continuity_notes: continuity-notes.md
continuity_notes_sha256: <连续性记录摘要>
```

`scene_images_sha256`使用内联JSON对象，按场次完整记录实际场景图摘要。仅已获场次授权、带阻塞标记的无图draft可暂缺对应图片与摘要，不据此晋升approved。

AI在Stage1读剧本时区分实际发声、画面文字、拟声和其他引用，随后在既有`dialogue.json`中保存原文及各镜实际发声位置；Stage3沿用已批准分镜，在既有编译记录中注明实际发声。程序只定位和比较这些明确数据，不从引号或“说/哭声”等词反推语义，不新增用户表单或审核阶段。

```json
{
  "dialogue": ["别进去。"],
  "source_speech": ["别进去。"],
  "stage1_speech": {
    "1A": [],
    "1B": ["别进去。"]
  }
}
```

`dialogue`是权威剧本中按真实发声顺序列出的原文；`source_speech`定位这些文字在原剧本中的出现位置。`stage1_speech`覆盖全部且仅主序列镜号，定位每镜画面内容栏中真正发声的文字，无对白镜头使用`[]`。可见标牌、文件文字或表演对原词的引用不因此成为发声记录。

定位项通常直接写原文字符串，前提是它在相应正文中只出现一次。同一文字出现多次时，使用`{"text":"禁止入内","occurrence":2}`明确选择第几次出现；occurrence从1开始，按该正文中相同字符串的非重叠出现顺序计数。程序检查文本真实存在、出现位置有效、顺序和不重叠，再核对原文；不为作者猜默认位置。正常换行与`<br>`统一后定位，不改原字或标点。原句跨镜分配时各镜只记实际发声的连续部分，整体字句与顺序仍须一致。

无对白源明确用`source_speech: []`及`dialogue: []`，各主镜均有空的发声数组。记录由生成代理在原步骤自动维护；选中的是否真是发声、是否漏标或新增了声音、是谁说的、声音落在哪个画面上，仍由原有对源内容复核负责。记录与字串核对不能自证这些语义成立。对源复核须直接读原剧本和完整镜头正文，核对全部实际发声及归属；来源选择、清单和成稿同时漏掉同一句时，三者相符也不能算对白完整。

旧稿的裸字符串数组或缺定位对象按[旧对白记录接入当前制作](shot-revision.md#旧对白记录接入当前制作)处理：旧稿与旧清单原件不改，在当前制作副本及新记录中保留原`dialogue`并补齐定位，再同步当前范围的引用。仅补内部记录不改变已有内容批准，也不要求用户填表；源文或导演内容改变仍按原有批准边界。没有定位依据时程序报告内部记录尚缺，不把它报成台词本身错误，也不默默按引号猜后宣称通过。


`director-plan.md` 在七列表格前保存整场演出、观看与连接决定，使用导演核心规定的独立元数据，不依赖未来分镜。`continuity-notes.md` 只记录方案段落如何落实到镜号、真实偏差、修订及限制，不重复造第二份设计。用户确认完整 Stage 1 时连同当前方案一起确认；修改方案或批准状态后同步其引用摘要，不能让旧方案继续作为当前依据。

没有引号、采用角色名独立一行的原剧本不必改写。对白清单可设 `source_format: "lines"`，并用 `source_ranges` 逐段精确选择对白本身所在行，排除角色标题和舞台说明；每个区间对应一段对白，换行按空格连接。`quoted`只在已显式声明的`source_ranges`内按引号语法读取原文，不再默认扫描整份剧本；范围由AI确认只包含实际发声。两种来源定位方式择一使用；声明`source_ranges`时不再填写`source_speech`，避免一份记录中存在两套不同依据。源文范围是否完整、是否归属正确人物仍需复核。

原文采用 `角色名：对白` 同行写法时使用 `speaker_lines`，例如 `{"source_format":"speaker_lines","source_ranges":[[12,13],[16,16]],"source_speakers":["师爷","甲"],"dialogue":["第一行对白。 接续对白。","第二句。"]}`。每个闭区间只选一次发言，首行必须包含对应声明角色的标签和中文或英文冒号；`source_speakers` 与区间逐段一一对应，角色名内部及周围的普通空格可不同（如 `师  爷：`）。只剥离匹配成功的首个角色标签，续行按空格连接，正文冒号及引语保留，不按冒号猜角色，不修改原剧本或把角色标签写进对白。

错角色、缺范围、角色数组不对应、空对白会拒绝；区间内再次出现已声明角色的非引语标签也会拒绝，应拆成独立发言区间。声明角色不能遗漏实际发声人。未声明标签与正文中的冒号文字、引用语义、范围完整性仍须对原文复核；此模式只检查源角色标签与提取内容，不自动认证 Stage 1 画面由谁发声，也不认证画面可见性。这些是来源格式的读取方式，不认证输出的发声归属；`stage1_speech`仍须按实际镜头维护。

先由完整状态推导当前机位能看见什么，再写画面内容。画外的手保留道具占用，但不能因账本里有这条状态而写进头肩近景。关键动作必须看清却在画幅外时，退回导演设计调整景别、运镜或拆镜；不能直接删剧本事实，也不能在 Stage 3 静默改方向或动作。

局部修订的编号、实际旧稿与完整旧新映射按[修订协议](shot-revision.md)绑定，不能仅以局部声明解除规范编号检查。局部修订更新受影响状态与镜头，沿依赖传播至后续起止状态、受光和片段边界。输入或记录变化时旧摘要失效；核对内容后才更新摘要，不为通过检查机械重算。记录不含自身或 Stage 1 摘要，避免循环绑定。

新生成稿运行 `scripts/validate_v2_shotlist.py <Stage1.md> --require-plan`。用户提供的外部已批准分镜无前置方案时，可不加此标志校验来源与转换，不倒造方案，也不声称验证了其前置设计。旧 `validate_shotlist.py` 仅用于继承格式检查。新入口检查格式、输入绑定和已声明发声的原文顺序，允许同一句连续拆到相邻镜头。表演引用、画面文字及其他声音不靠关键词排除，而由AI按真实用途在记录中区分；程序不认证未声明内容的语义。

**摘要只证明文件一致，不证明方案早于镜头形成或方案正确；字符串检查也不能证明说话人或物理关系正确。** 剧本到清单是否完整、对白归属、肩侧、背景和动作结果仍须依据底表实际复核。

叙述层的分析标签检查不应侵入原文对白；对白里出现“轴线”等词仍须原样保护。运动的起幅、触发、过程、切出构图及持续/停止状态由内容复核判断，不能凭是否出现“最终”“停稳”等词放行或拒绝。结构通过不表示这些内容已完成验证。

## 额外输入与项目策略

按 `project-input-schema.md` 声明实际使用的 `scene_facts/scene_facts_sha256`、可选 `input_manifest/input_manifest_sha256`。清单记录额外文件与摘要以及描述/数值光影、项目追加词表和已明确的对白授权。Stage 2/3沿实际Stage 1继承，核对其当前文件；不允许下游自建另一套策略。旧稿未使用额外文件时不强制造清单。声明和摘要正确仍不证明源是最新、内容完整或作者归属正确。

## Stage 2

运行 `scripts/validate_v2_stage2.py <Stage2.md>`，读取实际 Stage 1 文件并检查批准状态、project/episode、场次、场景图及当前输入。摘要不能填占位符。内部 `validate_text` 只检查卡片格式，不可作为来源批准的完整依据。

## Stage 3

保留 `source_stage1`、`stage1_sha256`、`source_stage2`、`stage2_sha256`；多场次 Stage 2 文件及摘要按同样顺序逗号分隔，覆盖全部且仅当前场次。增加：

```yaml
stage3_bindings: stage3-bindings.json
stage3_bindings_sha256: <编译记录摘要>
```

展开前根据已批准 Stage 1/2 创建编译记录，逐镜覆盖主序列。卡名属于本场，选定卡完整展开、不改写，未选卡不混入；卡名和记录标签不进入提示词正文：

```json
{
  "source_stage1_sha256": "<当前 Stage 1 摘要>",
  "shots": {
    "1A": {"fixed_cards": ["光影·角色甲"], "speech": []},
    "1B": {"fixed_cards": [], "speech": ["别进去。"]}
  }
}
```

每镜的`speech`按同样的字符串/occurrence方式，定位本镜提示词`动作/表情：`正文中实际发声的文字，必须显式给出数组。程序对照Stage1已声明的发声内容；不从其他类别的引号推断台词。旧编译记录由代理在当前制作副本的原有编译步骤补齐，历史记录原件保持不变；不增加用户表单或新的记录种类。

同类视觉卡片可合并类别标签，各卡正文按已选顺序完整保留，以换行分开；不得自由改写、删句或混入未选条件。程序与导出共同执行相同组装方式，不会要求一边完整照录、多卡展开后又因同标签被拒。

单镜光态变化等不能由复用卡承载时，在该镜增加 `exceptions`：

```json
{
  "fixed_cards": [],
  "speech": [],
  "exceptions": {
    "光影": {
      "text": "光影：本镜完整物理光影正文。",
      "basis": "当前已批准调度为什么需要单镜变化。",
      "stage1_evidence": "Stage 1 本镜画面内容里的连续原文"
    }
  }
}
```

例外只允许光影、背景、环境、群演或外观，正文仍执行其既有规则。它不是改动前阶段事实的授权；证据不成立或差异无法解释时退回对应阶段，不得临时添加例外绕过失败。

仅交付表格时运行 `scripts/validate_v2_prompts.py --stage3 <Stage3.md>`；可选 `--stage1` 必须与声明解析到同一文件。交付完整任务则直接运行下节`generation_tasks.py`，它已经调用相同Stage3来源/格式检查，无需事先重复。检查来源/批准/摘要、镜号全集/顺序、逐字分镜内容、时长与累积区间、30秒上限、对白、固定卡及单镜例外。坏行直接失败。仍只输出approved或生成前阻塞清单，不恢复draft和二次批准。

机器检查确定的输入输出关系；代理现在就对照完整场面评审导演设计、分镜与提示词中的状态、可见性、对白归属、表演、节奏和制作条件。提示词载荷实际收到什么也必须核对，不能用已绑定输入代替传入内容。具体未定项限定相关结论，视频执行效果另行验证。描述性光影不以亮/暗/方向等关键词认证其物理合理性；项目明确数值模式的格式要求保留。

## 实际任务输出

需要独立反应插入后回用主素材时，在Stage 3绑定 `generation_plan/generation_plan_sha256`，使用 [生成任务Schema](generation-task-schema.md)。任务计划、参考文件、源镜及真实连接依据一起校验；成片顺序保持不变。`generation_tasks.py`输出每任务文本、参考标签/文件映射及素材in/out到成片时间的映射，不在导出时调用模型。没有计划的旧稿仅导出原连续任务。

参考标签不是参考已上传的证据；真实素材身份、媒体规格、入口参数、生成与回剪仍须实际检查。

## 内容判断与末尾格式

摄影机高度/角度、画面是否提前描述落幅、文字是否表达真实未解决条件，由代理阅读源文和当前镜头判断。不能通过“眼平”“最终”“待确认”等词的出现与否作语义放行或拒绝；明确标记的🔴阻塞、空卡/TBD占位、缺失来源及摘要不一致仍会阻止批准交付。

无配乐和无字幕是项目默认制作要求。每个完整任务开头固定为`全片要求：不添加背景配乐，不生成字幕。`，末尾保留`无配乐无字幕`，不追加其他全片要求解释；不把作者逐镜写中某句当成理解正确的证明。作者可等义表达或不逐镜重复；仅交五列表时由模型在交付说明表达该要求。工具只整理可明确识别的旧尾句格式，不推断任意同义句，不改其余正文、原对白和源文件。内容复核仍须检查提示词没有与项目要求相反的内容。

## 创作表达与上游一致性不能混为一类

Stage1的高度/运动是否说清，由导演内容复核判断，不以“眼平”“固定”等词表存在性认证。Stage3仍须继承已经批准的摄影机信息：焦段、景别、机位/肩侧/路径和运动不能自行改变。程序核对明确的数值、结构及指定照录关系，不以景别/机位/运动词是否相同认定拍法改变；这些含义由原内容复核对源判断。原已保留的运动词集合差异仍仅作非阻塞`WARNING`，不能据此判定拍法已改。校验和导出入口显示镜号及前后摄影机描述，导出还在已有`edit-map.json.content_warnings`保留同一线索，不写入提示词。

在原编译内容自查或接收式审读的对源步骤处理这些提醒：确认等义且专业准确，保留原句继续，不补词、不要求提醒清零，不另建豁免表或审批；确认运动、方向、路径、次序或切出条件被改动/遗漏，在原失真步骤修正。导出成功或无提醒都不等于内容通过，集合相同与未命中词表的表达同样按完整拍法审读。记录是本次源/稿的差异快照，不是自动判错或已处理证明；真实修订按现有记录传播，不改旧快照伪装已解决。

## 专业规范与检查实现的边界

检查程序放宽不改变正式成稿的专业要求。模型按摄影机写法与七列schema，把输入意图整理成准确的景别、焦段、机位、高度/角度和稳定/运动术语，并在既有内容复核中检查其与实际镜头一致。无法命中程序词表不能直接证明拍法错误，命中“推”“升”“固定”等字也不能证明专业用法正确。原规范仍然生效；修的是识别与执行方式，不降低表达标准，也不增加新的审批层或用户填表工作。已批准的上游摄影机信息继续按原约定继承保护。

## 检查器的职责边界

同义表述不因换词而失败；实际语义、摄影术语是否准确、表演beat、观看与空间关系、群演和声音来源、任务自足性由原有内容复核对源判断。机器不再以“哭声/笑声出现两次”“声音段含引号”“画面里有轴线”等词面现象下语义错误结论，也不新增这些弱提醒。

程序仍严格核对来源文件与摘要、镜号全集/顺序、时长及上限/授权、明确毫米参数、已声明发声和指定照录内容。焦段按数值和单位读取，支持小数与变焦起止值，不能把识别范围暗中当作模型能力上限；参数可读取不等于拍法可行。语义上把横移改成摇摄等实质变化仍须在内容复核修正，不因程序通过获得许可。

来源声明与发声记录不是独立真实性认证。AI必须在原有源文审读中确认分类完整、无虚构发声或错归属；若发现真实冲突，仍回到相应步骤修正，不能因为程序已通过就交付。明示的项目词表策略保留，以记录中的真实发声范围区分对白和其他文字，不把所有引号都当成对白豁免。
